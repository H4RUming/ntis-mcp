# NTIS MCP 서버

NTIS(국가과학기술지식정보서비스) OpenAPI로 국가R&D 과제, 성과(논문·특허), 연구보고서를 바로 찾고 집계하는 MCP 서버입니다. 자료를 쌓아 두지 않고 질문이 올 때마다 NTIS에 요청합니다.

지원사업 공고는 NTIS OpenAPI로 받을 수 없어 여기에 없습니다. 공고(기업마당)는 별도 저장소의 MCP 서버들이 맡고, 이 서버들을 묶어 쓰는 채팅도 별도 저장소입니다.

## 설치와 실행

Python 3.11 이상이 필요합니다(설정 파일을 `tomllib`로 읽습니다).

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

승인키는 설정 파일에 넣습니다.

```bash
cp config.example.toml config.toml && chmod 600 config.toml   # config.toml 은 git 에 올라가지 않는다
# config.toml 의 [ntis] api_key 에 승인키를 적는다 (ntis.go.kr → 데이터활용 → OpenAPI 에서 발급)
.venv/bin/python -m ntis.check                                 # 실제 요청 10여 번으로 키와 검색 문법 확인
.venv/bin/python -m ntis.mcp_server --transport streamable-http --port 8768
```

로컬 엔드포인트는 `http://127.0.0.1:8768/mcp`입니다. 서버는 `127.0.0.1`에만 바인딩합니다. 로컬 MCP 클라이언트에서는 `--transport stdio`(기본)도 쓸 수 있습니다.

키가 없어도 서버는 뜨며, 그때는 모든 도구가 키를 어디에 넣어야 하는지 알려 줍니다. 서버를 띄워 둔 채 `config.toml`을 고쳐도 다음 요청부터 반영됩니다. 환경변수 `NTIS_API_KEY`가 있으면 그 값이 우선하고, 다른 위치의 설정 파일은 `--config` 또는 환경변수 `RND_CONFIG`로 줍니다.

## MCP 도구

- `search_projects`: 검색어(띄어 쓰면 AND, `|`는 OR, `!`는 제외)와 기준년도·부처·수행기관·사업명·연구책임자 조건으로 과제를 찾습니다.
- `count_projects`: 같은 조건의 과제 수를 연도·부처·수행기관·전문기관·사업·표준분류·수행주체·연구개발단계 중 하나로 집계합니다. NTIS가 직접 센 값(NAVIGATION)을 쓰므로 요청 한 번으로 끝납니다.
- `get_project`: 과제고유번호로 한 건.
- `search_results`, `count_results`: 과제에서 나온 논문·특허 검색과 집계.
- `search_reports`: 연구보고서 메타정보(제목·초록·목차·원문 주소). 본문은 받을 수 없습니다.
- `lookup_term`, `lookup_class_code`: 국가R&D 용어사전, 과학기술표준분류·국가중점기술 코드.
- `ntis_status`: 키 등록 여부, 설정 파일 위치, 마지막 오류.

## 알아둘 점

- **대외 제공 항목 제한.** NTIS는 과제 정보를 웹·모바일 같은 대외 서비스에 쓸 때 과제명, 과제고유번호, 기준년도, 예산사업명, 연구책임자, 과제수행기관, 부처명, 총연구기간, 당해연도 연구기간, 정부투자연구비, 총연구비, 연구내용(250자 내외), 한글·영문 키워드만 내보내도록 정해 두었습니다(과제검색 매뉴얼 1.2). 설정의 `external_use = true`(기본)이면 이 항목만 돌려주고 나머지는 NTIS 과제 상세 페이지 주소로 대신합니다. 내부에서만 쓸 때 `false`로 바꾸면 연구목표·기대효과·참여연구원·분류까지 나옵니다.
- 과제는 기준년도마다 한 건씩 등록됩니다. 다년도 과제는 연도 수만큼 세어지고, 연구비는 그 한 해의 금액입니다.
- 부처 이름은 정부 조직 개편으로 바뀌므로, 부처 조건을 걸기 전에 `count_projects(group_by="ministry")`로 실제 표기를 확인하는 편이 안전합니다.
- 승인키는 요청 주소에 실려 가므로 로그·오류 문구에 남지 않게 가립니다(NTIS는 거절한 키를 오류 문구에 그대로 돌려줍니다).
- 요청은 한 번에 하나씩 `delay` 간격으로 보내고, 같은 요청의 답은 `cache_ttl` 동안 다시 씁니다.

- 최근 연도 하나만 고르면 NTIS가 수행기관 집계를 비워 보낼 때가 있습니다(연도 범위를 넓히면 나옵니다). 이때 도구는 0건이 아니라 `caution`으로 알립니다. 같은 기관이 표기 차이로 나뉘어 나오기도 합니다(서울대학 / 서울대학교).
- 용어사전은 과학기술 용어 위주라 연구행정 용어(간접비 등)는 없는 것이 많습니다.

## 검색 문법의 근거

검색 문법은 NTIS 매뉴얼(과제검색·성과검색·연구보고서·용어사전·분류코드, 2025-10~12판)을 따르되 실제 응답으로 확인했습니다(2026-11-18, `ntis.check` 15개 항목 통과). 매뉴얼과 다른 점이 여럿 있습니다: 파라미터 이름이 표와 예시에서 서로 다르고, 연구보고서 응답은 XML 규칙에 어긋나며(`&`와 강조 태그가 그대로 들어 있음), 집계 이름 일부가 매뉴얼과 다릅니다. `ntis.check`는 필터를 건 건수를 NTIS의 집계값과 맞춰 봅니다. 검색 결과가 이상할 때 돌려 봅니다.


## 구성

| 파일 | 내용 |
|---|---|
| `ntis/client.py` | NTIS 요청, XML 해석, 요청 간격·캐시, 승인키 가리기 |
| `ntis/query.py` | 결과 다듬기(대외 제공 항목 제한 포함), 집계, 용어·분류코드 |
| `ntis/mcp_server.py` | MCP 도구 9개 |
| `ntis/check.py` | 실제 요청으로 키와 검색 문법 확인 |
| `appconfig.py` | 설정 파일(`config.toml`) 읽기 |

## 테스트

```bash
uv pip install --python .venv/bin/python pytest
.venv/bin/python -m pytest -q
```

테스트는 가짜 NTIS 응답으로 돌며 네트워크와 승인키가 필요 없습니다.
